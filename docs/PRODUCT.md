# 生长相册 GrowAlbum · 产品与技术文档（现状版）

> 本文档描述**已经实现并验证过**的能力，与 `docs/ARCHITECTURE.md`（模块分层）、`README.md`（快速开始）配套。
> `ComicDrama.md` 是最初的立项设想（漫剧工厂方向），已被本项目收敛为"个人影像"，仅作历史参考。

---

## 1. 一句话定位

**把你的照片，养成一部短片。**

素材驱动创意的个人影像工坊：照片是主角，模型负责讲故事、挑画面、配旁白、加运镜。

---

## 2. 实际核心流程

```
上传照片（个人相册）
   ↓ 可选：AI 打分（按用途评分，任务化、可取消）
   ↓ 可选：读图写故事（模型根据素材写剧本，一键立项）
→ 创意解析 Brief（题材/基调/钩子/关键词，由文本模型产出）
→ 剧本（节拍 + 角色卡）→ 分镜（景别/运镜/情绪/动作）
→ 提示词槽位组装（风格/一致性/光效/负面 预设拼接）
→ 关键帧：① 直接用你的照片（0 元）② 或模型生成（0.02 元/张）
→ 可动性预判（自动决定哪些镜头值得花视频模型的钱）
→ 图生视频（按镜头计费，可叠角色参考图）
→ 配音（按镜头对齐）+ BGM 混音（人声处自动压低）
→ 合成导出：1080×1920 / 15 秒 / H.264 + AAC
→ 一致性检查（挑出"跑样"镜头）→ 审核（合规 + 图文一致性）
→ 发布包（标题/简介/标签 + AI 生成标识写入文件元数据）
→ 投放数据回填 → 预设效果排行 → 新项目推荐最优组合
```

---

## 3. 架构（真实实现，非规划）

```
web/                Vue 3 单页应用（零构建步骤，组件化：菜单栏 / 视图 / 面板）
src/
  providers/        模型注册表：llm | image | i2v | tts，可换厂商、配置热加载
  workflow/         工作流引擎 + 节点库 + 模板
    engine.js       按「产物可用性」校验并执行，记录 nodeRuns，支持单节点重跑与暂停闸门
    nodes/          11 个节点，每个声明 requires / produces / canRun / run / fallback
    templates/      vertical-15s / album-mv-15s / draft-select-refine（+ 自定义模板）
  agents/           创意 Agent、总控 Agent
  services/         相册、提示词库、缓存、成本护栏、视觉理解、数据分析、批量、ffmpeg
  domain/           数据模型与纯函数：brief / preset / gallery / project / jobs / pricing
docs/               架构与方案文档
data/               运行时数据（gitignore）：项目、相册、预设、缓存、批次
```

**与最初设想的差异（重要）**：没有引入 Temporal/Airflow 工作流引擎、Kafka 消息队列、Milvus 向量库、S3 对象存储。实际采用的是**自研轻量引擎 + 文件系统存储**——对单机量产场景更简单、更可控，且已经内置了缓存、成本护栏、断点续跑、单节点重跑。

### 3.1 三个关键机制

| 机制 | 说明 |
| --- | --- |
| **降级链** | 每个付费节点都有兜底：i2v 失败→轻动态；图像失败→面板占位；TTS 失败→环境音床；文本失败→内置模板。**永远出得来片** |
| **成本护栏** | 付费节点调用前先估算，超过预算立即中止；每步花费累加进 `project.spend` |
| **内容缓存** | 关键帧 / 图生视频 / 配音 三级缓存（按内容哈希），**重跑不重复付费** |

## 5. 未实现 / 已知限制（诚实清单）

| 项 | 说明 |
| --- | --- |
| 时间线编辑器 | 现在是分镜级的顺序合成，没有拖拽式多轨时间线 |
| 团队协作 / 多用户 | 单用户单机；无账号体系、无权限、无并发隔离 |
| 资产市场 / 模板市场 | 未做 |
| LoRA / 人脸 ID 一致性 | 未做；当前靠参考图 + 多图 media 参考 |
| 逐词字幕 / ASR 时间轴校正 | 未做；当前字幕按镜头硬对齐 |
| 音色库 / BGM 库 | 机制就绪（`data/bgm/<情绪>/` 自动优先），缺素材 |
| 低分图自动重绘（agent 循环） | 未做；这是将来接 LangGraph 最自然的切入点 |
| A/B 变体对比 | 三段式里支持"方向对比"，但同一 Brief 的多版本并排比较未做 |
| 关键帧状态口径 | 用相册照片时的计数显示不准（功能正确，显示有误） |
| API 契约文档 | 未写；为将来接入外部编排（LangChain/LangGraph）准备 |
| 批次续跑验证 | 已实现，仅在"重启后恢复批次记录"层面验证过 |

## 9. 部署

```bash
cp env.example.yaml env.yaml     # 填模型 Key（该文件不入库）
docker compose up -d --build
# http://localhost:8787
```

数据与产物全在 `./data`（已 gitignore）：项目、相册、提示词库、缓存、批次。备份这一个目录即可。

## 10. 设计原则

1. **流程固定、节点可见**：不做自由连线的节点图，但每个节点的启停/参数/状态可见可改
2. **失败必降级**：任何模型不可用都要能出片，并在任务面板标明降级原因
3. **花钱有护栏**：调用前估算、超预算中止、每步记账
4. **重跑不重复付费**：内容哈希缓存贯穿关键帧/视频/配音
5. **诚实的能力边界**：未做的写在文档里，而不是留给用户去发现
