# 漫剧工作流改造方案 v0.2（自定义编排 + 提示词分组 + 个人相册）

> 前提：模型全走你自接的 API Key，不在本地跑开源权重。
> 目标：**能自己搭工作流**，但复杂度压在 ComfyUI 的 1/5 以内。

---

## 0. 一句话结论

| 问题 | 结论 |
| --- | --- |
| 要不要用 Python？ | **不需要。** 相册、编排、提示词、ffmpeg 合成都不是 Python 的强项领域；只有「本地跑开源模型 / 本地人脸聚类」才需要，可以后面加可选 sidecar |
| 自定义工作流怎么做？ | **节点库 + 线性编排**：节点类型我们提供，你能增删、排序、启停、改参、存成自己的模板；不做自由连线和类型系统 |
| 相册怎么用？ | 相册是**素材源**：既能直接拼成 MV，也能当图生视频的首帧、当参考图、当分镜画面 |
| 提示词？ | 库 + **分组树**（画风 / 运镜 / 光线 / 一致性 / 负面 / 音频情绪），从菜单栏按槽位多选 |

## 1. 为什么这次仍然不用 Python

你的三个新需求逐条拆开看，需要的能力是：

| 需求 | 实际要做的技术活 | 语言是否相关 |
| --- | --- | --- |
| 自定义编排工作流 | 存 JSON、校验、按顺序执行、记状态 | 无关（Node 更省事，与前端同语言） |
| 提示词分组 | CRUD + 拼装字符串 | 无关 |
| 个人相册 | 文件上传、缩略图、分组、索引 | 无关（sharp/ffmpeg 都有现成方案） |
| 相册 → 创意视频 | ffmpeg 拼装（Ken Burns/转场/BGM）或调 API | 无关 |
| 模型调用 | 全是 HTTP API | 无关 |

**会改变结论的只有三种情况**：① 想在本地跑 Wan/SVD/AnimateDiff 这类开源视频模型；② 想做本地图片理解（人脸聚类、美学打分、自动选图）；③ 团队本来就是 Python 栈。
其中 ② 也可以先用视觉模型 API 顶替（上传图问模型「这批图里哪些适合作钩子镜头」），不必为此换语言。

> 将来真要用 Python：做成**可选 sidecar 服务**（只管本地推理），编排层继续 Node。不要为一个能力把整条链路换语言。

## 2. 工作流：从「固定链」升级为「可自定义编排」

### 2.1 三层结构（复杂度可控的关键）

```
模板层：内置模板（竖屏漫剧 15s / 相册 MV / 图文混剪）+ 你的自定义模板
   ↓
编排层：在模板上增删节点、排序、启停、改参数      ← 你要的自定义，在这一层
   ↓
参数层：每个节点的模型、提示词槽位、时长、降级策略
```

**允许**：加节点、删节点、拖动排序、启停（旁路）、改参数、复制一份存成「我的模板」。
**故意不做**：自由连线、自定义节点类型、输入输出类型系统、子图嵌套。

> 理由：视频流水线的数据流向天然线性（文本 → 图 → 视频 → 音频 → 合成），自由连线 90% 的用法是「把某个节点接到别处」，用「启停 + 参数」就能覆盖；而它会让你校验、状态、重试、复现全部复杂 3–5 倍。

### 2.2 节点库（固定 12 种，够搭出各种片子）

| 类别 | 节点 | 作用 | 依赖 Key |
| --- | --- | --- | --- |
| 文本 | `brief` 创意解析 | 一句话创意 → Brief | 可选（无 Key 走规则） |
| 文本 | `script` 剧本 | Brief → 节拍 + 角色卡 | 可选 |
| 文本 | `storyboard` 分镜 | 剧本 → shots[] | 可选 |
| 素材 | `prompt_assembly` 提示词组装 | 库 + 槽位 → 每镜头最终 prompt | 不需要 |
| 素材 | `image_source` 图片来源 | 模型生图 / 我的相册 / 占位面板 | 视选择而定 |
| 图像 | `keyframe` 关键帧 | 出 9:16 关键帧（支持参考图） | 图像 API |
| 图像 | `image_edit` 局部重绘 | 换装 / 换背景 / 改表情 | 图像编辑 API |
| 视频 | `shot_video` 镜头视频 | 关键帧 → 3s 动态 | 图生视频 API |
| 视频 | `album_mv` 相册 MV | 相册图片 → 带运镜/转场的片段 | **不需要** |
| 音频 | `voice` 配音 | 台词 → 语音 | TTS API |
| 后期 | `compose` 合成导出 | 拼接 + 字幕 + 调色 + 9:16 导出 | 不需要 |
| 后期 | `review` 审核运营 | 风险检查 + 标题/简介/标签 | 可选 |

每个节点声明 `requires` / `produces`，前端实时校验（例如删掉 `keyframe` 却留着 `shot_video`，提示「缺少关键帧输入」），保存前后端再校验一次。

### 2.3 模板示例：相册驱动的一条链

```js
{
  id: 'album-mv-15s',
  name: '相册 MV 15 秒',
  video: { width: 1080, height: 1920, fps: 25, shotSeconds: 3, shots: 5 },
  nodes: [
    { id: 'brief',    provider: 'llm.default', enabled: false },
    { id: 'album_mv', params: { albumId: 'alb_xxx', pick: 'sequential', transition: 'fade', bgm: 'ambient' } },
    { id: 'compose',  params: { subtitle: true, title: true } }
  ]
}
```

同一套模板系统既能表达「全自动漫剧」，也能表达「相册秒出片」。

### 2.4 节点契约

```
canRun(ctx)   -> { ok, reason }          // 缺 key / 缺上游产物 / 参数非法
run(ctx)      -> { assets, meta, cost }  // 执行
fallback(ctx) -> { assets, degraded }    // 降级实现（可空）
```

状态：`待执行 / 执行中 / 成功 / 降级成功 / 失败 / 跳过`；**支持单节点重跑**（复用上游产物，不从头来）。

## 3. 个人相册模块

### 3.1 定位

相册是**素材源**，与「模型生成」平级，同时承担三件事：

1. 存你自己的图（上传 + 分组 + 打标）
2. 作为生成素材（首帧 / 参考图 / 风格参考 / 直接当画面）
3. 沉淀产物（生成的关键帧、成片封面可一键入库，形成可复用资产）

### 3.2 数据模型

```
Album  { id, name, coverPhotoId, description, tags[], count, createdAt }
Photo  { id, albumId, file, thumb, width, height, bytes,
         source: 'upload' | 'ai' | 'keyframe' | 'poster',
         tags[], note, palette[], createdAt }
```

存储：文件落 `data/comicdrama/gallery/<albumId>/`（原图 + `thumbs/`），索引先落 JSON（`gallery/index.json`），后续换 SQLite 只改 storage 层。

### 3.3 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST | `/api/gallery/albums` | 相册列表 / 新建相册 |
| DELETE | `/api/gallery/albums/:id` | 删除相册（二次确认） |
| GET | `/api/gallery/albums/:id/photos` | 相册内照片 |
| POST | `/api/gallery/albums/:id/photos` | 上传（multipart 多图；自动缩略图 + 读尺寸） |
| POST | `/api/gallery/photos/:id/tags` | 打标 / 备注 |
| DELETE | `/api/gallery/photos/:id` | 删除照片 |
| POST | `/api/gallery/albums/:id/auto-tag` | 视觉模型自动打标（可选，需 Key） |
| POST | `/api/gallery/albums/:id/mv` | 用该相册直接生成 MV（走工作流） |

### 3.4 UI（菜单栏新增「我的相册」）

- 左：分组树（相册列表 + 新建 / 重命名 / 删除）
- 右：照片网格（懒加载缩略图，hover 显示信息，点开大图）
- 顶部：上传（拖拽/点选，支持多选）、批量删除、批量打标、**「用所选生成视频」**
- 选中若干图后可直接：`设为角色参考` / `加入素材池` / `作为首帧生视频` / `拼成 MV`

### 3.5 相册驱动的四种生成模式

| 模式 | 说明 | 需要 Key | 成本 | 适用 |
| --- | --- | --- | --- | --- |
| **A. 相册 MV** | 图片 + Ken Burns 运镜 + 转场 + 字幕 + BGM，纯 ffmpeg | 不需要 | 0 | 相册回顾、图集短片、快速出片 |
| **B. 首帧生视频** | 每张图 → 图生视频 3s → 合成 | i2v | 高 | 让静态图动起来 |
| **C. 参考图生图** | 相册图当参考（角色/画风锁定），生成统一风格关键帧 | 图像 API | 中 | 主角一致、系列化内容 |
| **D. 混合** | 部分镜头用相册原图、部分用模型生成、部分用参考图 | 视情况 | 灵活 | 真人+漫画混剪、素材复用 |

模式 A 是**零 Key 可验收**的，建议作为第一个落地目标；B/C 属于后续增强。

## 4. 提示词库（菜单 + 分组）

### 4.1 分组树

```
提示词库
├─ 画风（style）        国漫赛璐璐 / 韩漫厚涂 / 水墨 / 美式漫画 / 写实电影感
├─ 运镜（camera）       缓慢推近 / 手持轻晃 / 环绕 / 拉远 / 上摇
├─ 光效（lighting）     侧逆光 / 冷色调夜景 / 霓虹 / 雨天反光 / 丁达尔
├─ 一致性（consistency）角色外观固定前缀 / 服装状态 / 场景锚定
├─ 负面（negative）     畸形手 / 多指 / 崩脸 / 水印 / 文字 / 变形
└─ 音频情绪（audio）    克制 / 压抑 / 急促 / 温柔 / 悬疑
```

分组可自定义（新增 / 改名 / 排序）。每条含：`槽位、文本、权重、标签、作用域（全局/项目）、变量占位符`。

### 4.2 用法

- 菜单栏「提示词库」入口：树 + 列表 + 编辑器 + 导入导出 JSON。
- 分镜表 / 关键帧面板：每个镜头的槽位下拉，从库里多选，**实时预览组装结果**。
- 组装顺序界面可见、可拖，一次调整全局生效：`style → consistency → scene → action → camera → lighting → extra`，负面单独拼接。
- 镜头同时保存 `preset_ids[]` + `resolved_prompt`（可复现「当时用的是哪几个预设」）。
- 相册照片也能挂提示词（某张图专属的风格描述），当参考图时一并带上。

## 8. 待定决策项

1. **工作流自定义粒度**：仅支持「增删节点 / 排序 / 启停 / 改参 / 存模板」，或需要支持**自由连线**（成本高 3–5 倍，且需引入类型系统与校验）
2. **相册的首要用途**：相册 MV（零 Key、无需视频模型），或首帧生视频（需配置图生视频的 Key）
3. **相册图片来源**：除了自己上传，是否要把「AI 生成的关键帧 / 成片封面」也自动入库，形成素材沉淀？
4. **补充提案取舍**：第 9 章列出 40+ 条，是否按 9.10 的 Top 5 优先级推进

## 9. 补充提案清单（v0.3 增量）

> 全部新增项都遵循一个原则：**能用 API 解决的不引入本地依赖**，尤其是「视觉理解」这一类。

### 9.1 视觉模型 API 替代本地 ML（重点方向）

这一组的共同好处：不需要装 Python / torch / CUDA，一个视觉 Key 全搞定；而且做的是本地模型很难做好的「语义理解」。

| # | 能力 | 做什么 | 落到哪里 | 需 Key | 复杂度 |
| --- | --- | --- | --- | --- | --- |
| 1 | 相册自动打标 | 识别场景/人数/时段/情绪/色调 → 自动生成标签与智能分组 | 相册 | 视觉 | 低 |
| 2 | 智能选图 | 从一组图里挑出最适合当**钩子/封面**的 N 张（构图、清晰度、主体占比、情绪强度打分） | 相册 | 视觉 | 低 |
| 3 | 叙事排序 | 把散图排成有起承转合的顺序，输出理由 → **直接变成分镜** | 相册 → 分镜 | 视觉 | 低 |
| 4 | 角色聚类 | 判断哪些图是「同一个人/同一个角色」→ 自动建角色卡 + 参考图组 | 相册 → 角色 | 视觉 | 低 |
| 5 | **风格反推** | 从你的相册图里反推风格/光线/镜头描述词 → 生成 style 预设，让生成的关键帧**跟你自己的审美统一** | 相册 → 提示词库 | 视觉 | 低 |
| 6 | 图 → 完整提示词 | 单图反推可编辑的完整 prompt（改造既有素材用） | 相册/关键帧 | 视觉 | 低 |
| 7 | 竖屏安全区检查 | 判断主体是否落在 9:16 安全区，给出重构图建议 | 相册/关键帧 | 视觉 | 低 |
| 8 | **相册 → 故事** | 给一组图让模型写脚本与台词（图片驱动创意），这就是「根据相册生成创意视频」的字面实现 | 相册 → 创意 | 视觉 | 低 |
| 9 | **i2v 可动性预判** | 判断这张图值不值得花 i2v 的钱（主体是否清晰、有无运动空间）→ 不值得的自动走 Ken Burns，**直接省钱** | 工作流决策 | 视觉 | 中 |
| 10 | 一致性打分 | 生成的关键帧 vs 角色参考图，输出是否走样 + 差异描述 | 审核节点 | 视觉 | 中 |
| 11 | 视觉审核 | 上传前 + 生成后做敏感/违规内容检测 | 审核节点 | 视觉 | 低 |
| 12 | 图文一致性 | 字幕和画面是否对得上（避免"文不对图"） | 审核节点 | 视觉 | 低 |
| 13 | 封面文案 | 看图写 6 字封面语（比纯文本模型更准） | 运营节点 | 视觉 | 低 |
| 14 | 去重与最佳帧 | 相似图去重、连拍里挑最佳一帧 | 相册 | 视觉 | 低 |

> 1/2/3/5/8/9 这六条是「相册」这条产品线真正的护城河：它们让**你自己的图**能驱动创意、风格和预算决策，而不是只能当装饰。

### 9.2 一致性工程（漫剧的生死线）

| 提案 | 说明 |
| --- | --- |
| 角色卡 + 参考图 + 固定 seed | 三件套锁定外观，节点参数里可分别覆盖 |
| 服装/状态机 | 角色在不同镜头的服装、伤势、情绪状态显式声明，避免前后矛盾 |
| 镜头级角色锁定 | 某个角色在某镜头强制复用同一参考图与 seed |
| LoRA 槽位（预留） | 以后接了训练好的角色 LoRA，直接填进去，不用改架构 |
| 一致性打分回环 | 见 9.1#10，不达标的镜头自动标记待重绘 |

### 9.3 成本与可靠性

| 提案 | 说明 |
| --- | --- |
| 成本预估 | 每个节点声明单价，编排时实时显示「这条链跑完约 X 元」 |
| 预算护栏 | 项目设预算上限，超限暂停并等确认（避免一个 bug 烧钱） |
| 素材缓存 | `prompt + provider + seed` 命中即复用，重跑不重复花钱 |
| 断点续跑 | 节点级产物落盘，失败后从断点继续（已有基础） |
| 单节点重跑 | 只重跑不满意的那个节点（已有设计） |
| 失败聚合 | 按 provider/节点统计失败原因，快速定位是 Key 问题还是模型问题 |
| 并发控制 | 每 provider 声明并发上限，避免限流 |

### 9.4 生产提效

| 提案 | 说明 |
| --- | --- |
| 批量生产 | 一次粘贴 N 条创意 → 队列依次出片（MCN 场景） |
| 变体生成 A/B | 同一 Brief 出两版（换画风 / 换首图 / 换钩子），并排对比 |
| 低清试片 | 先用低分辨率/低单价模型跑通，满意再出高清（省 60%+） |
| 模板市场（预留） | 你的模板可导出给别人用，也可以导入别人的 |
| 快捷键与批量操作 | 批量导入、批量渲染、批量导出提示词包 |

### 9.5 数据闭环（真正的增长点）

| 提案 | 说明 |
| --- | --- |

## 11. i2v 接入记录

### 11.1 可灵（Kling）

| 项目 | 结论 |
| --- | --- |
| 接口 | `POST {base}/v1/videos/image2video` 创建任务，`GET {base}/v1/videos/image2video/{task_id}` 查询 |
| 鉴权 | **只接受 JWT**（AccessKey + SecretKey 用 HS256 签名），不接受单纯 API Key |
| 验证结果 | 不带鉴权 → `1001 Authorization is empty`；带 Key → `1002 The token was expected to have 3 parts` |
| 状态 | 适配器已写好（自动识别 JWT/Key 两种模式），等 AccessKey + SecretKey |

### 11.2 阿里云百炼（DashScope）· Vidu 模型

| 项目 | 结论 |
| --- | --- |
| 模型 | `vidu/viduq3-drama_reference2video`（精品剧/AI 漫剧专用） |
| 定价 | 0.875 元/秒（720P 与 1080P 同价） |
| 其它可选 | `vidu/viduq3-pro-fast_img2video` 0.375 元/秒（720P）、`vidu/viduq3-pro_img2video` 540P 0.3125 元/秒 |
| 接口主机 | `https://maas.qianwenaiapi.com`（`dashscope.aliyuncs.com` 也可用） |
| 接口 | `POST /api/v1/services/aigc/video-generation/video-synthesis` + `X-DashScope-Async: enable`，任务查询 `GET /api/v1/tasks/{id}` |
| 鉴权 | ✅ 有效 |
| 状态 | ✅ **已跑通**（契约见下） |

**确认下来的请求契约**（关键：图片放在 `input.media`，且必须是**对象数组**）：

```json
{
  "model": "vidu/viduq3-drama_reference2video",
  "input": {
    "prompt": "镜头动作描述",
    "media": [{ "type": "image", "url": "<公网 URL 或 base64 data URI>" }]
  },
  "parameters": { "resolution": "720P", "duration": 5, "size": "720*1280", "watermark": false }
}
```

踩过的坑（避免重犯）：

1. **`media` 必须是 `[{type:'image', url}]` 对象数组**，传字符串数组会被判 `Missing required field 'images'`——报错里说的字段名和真实字段名并不一致，极具误导性（这也是卡了很久的原因）。
2. **不接受 `oss://` 地址**（官方临时上传换来的 oss:// 直接提交会失败），但**接受 base64 data URI**，所以本地关键帧无需图床，`DASHSCOPE_MEDIA_MODE=datauri` 已设为默认。
3. `parameters` 只认 `duration / resolution / size / watermark`；负面词不要单独传参，拼进 prompt 更稳。
4. 竖屏 `720*1280` / `1080*1920` 均已被接受。

**成本护栏**：`shot_video` 节点的 `limit` 参数按「尝试次数」限流，首次试跑建议 `limit: 1~2`。

### 11.3 一个值得重新考虑的设计（等契约确认后决定）

Vidu Q3 支持最长 16 秒、多镜头切换。这意味着 15 秒成片可以**一次调用生成整集**（给多张参考图 + 分镜提示词），
而不是 5 次单镜头调用。收益：角色/画风一致性更好（模型自己在同一段视频里保持一致）、
请求数从 5 降到 1。代价：单镜头重试粒度变粗（要重试只能重试整集）。

建议做成两种模式并存：`shot_video`（逐镜头，控制精细）与 `episode_video`（整集，成本与一致性更优）。

## 12. 图像 provider（百炼 Qwen-Image）接入记录

| 项目 | 结论 |
| --- | --- |
| 触发原因 | 视频后半段"没有图"：未配置图像模型时，关键帧为 ffmpeg 暗色占位面板（平均亮度约 33） |
| 模型 | `qwen-image-3.0`（**0.02 元/张**，一集 5 张 = 0.1 元）；可选 `z-image-turbo` 0.1、`qwen-image-2.1-pro` 0.25 |
| 接口 | ⚠️ 本账号**不支持异步图像调用**（`text2image/image-synthesis` 返回 403 `does not support asynchronous calls`） |
| 正确路径 | 走**同步** `POST /api/v1/services/aigc/multimodal-generation/generation`，返回 `output.choices[0].message.content[]` 里的 `image` URL，再下载落盘 |
| 竖屏 | `parameters.size = "720*1280"`，后续由合成节点统一裁到 1080×1920 |
| 状态 | ✅ 已跑通：关键帧节点 `模型出图 5 / 面板占位 0` |

同时把面板占位配色整体提亮（暗角从 `PI/5` 收到 `PI/12`、字幕带 `black@0.45` → `0.30`、渐变底色改用高明度配色），
保证"没配模型"时成片也不像黑屏。
